# Security policy

## Supported scope

The latest main-branch revision is the supported development version of PressFlow. This public educational project does not publish maintained security releases or promise production readiness.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/saadh472/pressflow/security/advisories/new) to share affected paths, reproduction steps, and potential impact. Do not put credentials, personal records, database files, or exploit details in a public issue. This student-maintained project cannot guarantee a response time.

## Safe local use

Use fictional records and dedicated demo accounts. Follow the README's session, credential, and deployment limits. Keep runtime databases and secrets outside Git, bind local demonstrations to loopback, and review updates before merging them. Public source access does not authorize access to another installation's records.

A shared service needs HTTPS, appropriate authentication and authorization, abuse controls, backups, and monitoring. Review the actual application behavior before exposing a server. Automated tests, dependency updates, and code scanning complement review; passing checks do not prove that a deployment is secure.
